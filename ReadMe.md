# 🌸 Sakura

Веб-платформа для бронирования и продажи земельных участков с интерактивной схемой. Проект для агентства недвижимости: клиент видит план посёлка, выбирает свободный участок кликом и бронирует его, агент управляет участками через админ-панель.

> **Статус:** учебный pet-проект, MVP в активной разработке.

## Возможности

- 🗺 **Интерактивная SVG-схема участков** — цвет участка зависит от статуса (свободен / забронирован / продан)
- ⚡ **Бронирование без перезагрузки страницы** — клик по участку обновляет схему через [htmx](https://htmx.org)
- 🔐 **Регистрация и вход** — сессии на cookie, пароли хешируются через bcrypt
- 👤 **Личный кабинет клиента** — список своих забронированных участков
- 🛠 **Админ-панель** — создание и редактирование участков (доступна только роли `admin`)
- 🚫 **Защита от повторного бронирования** — атомарный `UPDATE ... WHERE status = 'available'`

## Технологии

| Слой | Технология |
|------|-----------|
| Backend + рендеринг | Go, стандартная библиотека `net/http`, `html/template` |
| Интерактивность | htmx (подключается через CDN, без сборщиков и Node.js) |
| База данных | PostgreSQL 16 |
| Кэш / блокировки | Redis 7 (контейнер поднят, интеграция в планах) |
| Драйвер БД | [pgx v5](https://github.com/jackc/pgx) |
| Сессии | [gorilla/sessions](https://github.com/gorilla/sessions) |
| Пароли | `golang.org/x/crypto/bcrypt` |
| Окружение | Docker / docker-compose |

Весь проект написан на Go — отдельного фронтенд-фреймворка нет, HTML рендерится на сервере.

## Быстрый старт

### Требования

- [Go](https://go.dev/dl) 1.22+ (нужен синтаксис маршрутов с методами, например `GET /path`)
- [Docker Desktop](https://www.docker.com/products/docker-desktop)
- SQL-клиент (например, DBeaver) — по желанию

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<ваш-аккаунт>/sakura.git
cd sakura
```

### 2. Поднять PostgreSQL и Redis

```bash
docker-compose up -d
docker ps   # должны быть запущены sakura_postgres и sakura_redis
```

### 3. Создать таблицы

Подключитесь к базе (`localhost:5432`, база `sakura`, пользователь `postgres`, пароль `postgres`) и выполните:

```sql
CREATE TABLE users (
    id            SERIAL PRIMARY KEY,
    email         TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role          TEXT NOT NULL DEFAULT 'client',   -- client | admin
    created_at    TIMESTAMP DEFAULT NOW()
);

CREATE TABLE plots (
    id          SERIAL PRIMARY KEY,
    number      TEXT NOT NULL,
    area        NUMERIC NOT NULL,                   -- площадь, соток
    price       NUMERIC NOT NULL,
    status      TEXT NOT NULL DEFAULT 'available',  -- available | reserved | sold
    svg_points  TEXT NOT NULL,                      -- координаты полигона для SVG
    reserved_by INTEGER REFERENCES users(id),
    created_at  TIMESTAMP DEFAULT NOW()
);
```

> Если колонка площади у вас называется иначе (например, `area_sotka`), приведите SQL-запросы в `main.go` к одному имени.

Тестовые участки (сетка прямоугольников):

```sql
INSERT INTO plots (number, area, price, status, svg_points) VALUES
('1', 6,  500000, 'available', '10,10 110,10 110,80 10,80'),
('2', 8,  650000, 'available', '120,10 220,10 220,80 120,80'),
('3', 10, 800000, 'sold',      '230,10 330,10 330,80 230,80'),
('4', 6,  500000, 'reserved',  '10,90 110,90 110,160 10,160'),
('5', 12, 950000, 'available', '120,90 220,90 220,160 120,160');
```

### 4. Запустить приложение

```bash
go run main.go
```

Откройте <http://localhost:8080>.

### 5. Создать администратора

Зарегистрируйтесь на `/register`, затем выдайте себе роль в базе:

```sql
UPDATE users SET role = 'admin' WHERE email = 'ваш_email@example.com';
```

После этого станет доступна админка: <http://localhost:8080/admin/plots>.

## Маршруты

| Метод | Путь | Доступ | Описание |
|-------|------|--------|----------|
| GET | `/` | все | Схема участков |
| POST | `/plots/{id}/reserve` | авторизованные | Забронировать участок |
| GET / POST | `/register` | все | Регистрация |
| GET / POST | `/login` | все | Вход |
| GET | `/logout` | все | Выход |
| GET | `/dashboard` | авторизованные | Мои брони |
| GET | `/admin/plots` | admin | Список участков |
| GET / POST | `/admin/plots/new` | admin | Создание участка |
| GET / POST | `/admin/plots/{id}/edit` | admin | Редактирование участка |

## Как устроена схема участков

Каждый участок хранит в БД координаты полигона (`svg_points`, например `10,10 110,10 110,80 10,80`). Шаблон рисует их внутри одного `<svg>`, а CSS-класс `status-{статус}` задаёт цвет. Клик по свободному участку отправляет `hx-post` на сервер; сервер обновляет статус и возвращает обновлённое содержимое схемы, которое htmx подставляет внутрь `<svg id="scheme">`.

Реальные координаты участков можно получить, обведя генплан в Inkscape или Figma и экспортировав точки полигонов.

## Известные проблемы

- После клика по участку схема иногда пропадает до обновления страницы (F5) — идёт диагностика (проверяется несовпадение имён шаблонов и ответ сервера в Network).
- Секрет для подписи сессий зашит в коде — см. раздел «Безопасность».

## Безопасность

Проект учебный, перед публикацией в интернет обязательно:

- вынести секретный ключ сессий (`sessions.NewCookieStore`) в переменную окружения и сгенерировать длинную случайную строку;
- вынести параметры подключения к БД и пароль Postgres из кода в переменные окружения;
- сменить стандартный пароль `postgres`;
- включить HTTPS и флаги `Secure` / `HttpOnly` / `SameSite` для cookie;
- добавить CSRF-защиту для POST-форм;
- не коммитить `.env` и любые секреты в репозиторий.

## Деплой (план)

1. Написать `Dockerfile` (multi-stage build) и добавить сервис приложения в `docker-compose.yml`.
2. Арендовать VPS (Yandex Cloud, Hetzner и т.п.), установить Docker.
3. Запустить `docker-compose up -d --build`.
4. Привязать домен и настроить HTTPS (Nginx + Let's Encrypt).

При запуске приложения внутри Docker адрес БД в строке подключения нужно заменить с `localhost` на имя сервиса (`postgres`).
